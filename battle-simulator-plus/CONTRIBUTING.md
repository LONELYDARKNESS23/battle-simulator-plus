# Разработка RIFT

Игра использует только стандартную библиотеку Python 3.10+. Интерфейс — обычные HTML, CSS и JavaScript modules, без сборщика и сторонних игровых ресурсов.

## Проверки перед изменениями

```sh
python -X utf8 -m unittest discover -s tests -v
npm run check
npm test
```

Для форматирования Python можно установить инструменты в виртуальную среду:

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: . .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m ruff check .
python -m ruff format --check .
```

GitHub Actions выполняет Python-тесты на Windows и Linux с Python 3.10, 3.12 и 3.14; JavaScript-тесты проверяют жизненный цикл наблюдения и отбрасывание устаревших ответов. Для игры Node не нужен.

## Границы модулей

- `game/engine.py`: детерминированные правила, проверка действий и сохранений. ИИ не должен изменять характеристики или обходить `Battle.apply`.
- `game/commanders.py`: стратегические приказы и провайдеры. Новому адаптеру нужен `plan(battle, team)`; его ответ проверяется через `validate_orders`.
- `game/storage.py`: ограниченное чтение JSON и атомарная запись с уникальными временными файлами.
- `start.py`: локальный HTTP API, отмена запоздавших результатов, транзакционное применение хода и кеш состояния.
- `web/client-state.js`: планирование наблюдения и защита от устаревших ответов.
- `web/app.js`: управление и отрисовка. Неизменное поле не требует непрерывной перерисовки.

Новое правило сопровождайте тестом его результата, включая взаимодействия с ОД, укрытием, ответным огнём, победой и сохранением. Изменения интерфейса проверяйте в браузере на обычном и узком экране. Не увеличивайте расход запросов к модели без необходимости: один план на отряд и ход.

Не добавляйте `config.json`, сохранения, `.env`, локальные логи или содержимое `original/` в репозиторий. Шаблон конфигурации — `config.example.json`, секреты — в памяти сеанса или переменных окружения.

## Сборка архива

```sh
python tools/build_release.py
```

Скрипт собирает только разрешённые исходники, документацию и снимки интерфейса. Архив и его SHA-256 появляются в `dist/`; настройки и игровые сохранения туда не попадают.
